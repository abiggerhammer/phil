# Steve systems-pressure-test material

`lowering-contract.md` is the current Steve 0 mapping from the semantic/assurance witness into Phil's ADR-007/010/011/012 Systems IR. It remains the design-level description of the intended `StevePut`/`SteveGet` control flow, ownership, runtime checks, execution-topology scope, cost model, and eventual executable-promotion criteria.

`generalization-handoff.md` is the implementation/proof handoff extracted from that pressure test. It turns the four representation gaps into concrete generic Haskell and Rocq targets:

- first-class assumption authority on stage facts, including mixed transferred-plus-assumption facts;
- multiple exact assurance claims on one physical runtime site without duplicating physical realization or cost, while keeping runtime primitive/execution-profile identity, Systems-site identity, and assurance claim identity distinct;
- checked provider-capability possession and call authority, so absence of replace/delete authority is structural rather than inferred from unused calls;
- binding persistent assurance subjects to stable semantic owner/storage identity while borrowed views, target placement, and runtime representations remain observation/realization mechanisms.

The material here is intentionally design-first rather than an executable `SystemsArtifact`. The current upload-derived Systems implementation and proof corpus should be generalized, not copied around with Steve-specific exceptions. ADR-012 additionally requires the generic representation to remain execution-topology-neutral: the current host/CPU and LLVM call shapes are target-specific specializations, not definitions of physical Systems mechanisms.

The branch is synchronized through current main after PRs #46 and #47. That includes the Systems ownership/runtime proofs (#31), LLVM translation-validation proofs (#33), runnable compiler and typed scalar path (#32/#34), concrete Phase 0 LLVM translation certification (#35), checked Surface -> Systems scalar lowering and proofs (#36/#39), scalar preservation proofs (#37), semantic field projection and its proof/certification tranche (#38/#42), the first Phil-native Rocq proof-certificate path (#40), recognized-record ABI v1 (#41), the runtime-symbol identity amendment prompted by Steve Generalization 2 (#43), the implemented/translation-validated recognized-record ABI candidate and `PHIL-LLVM-CERT-002` (#44), the concrete runtime smoke realization (#46), and the proof-bound recognized-record certification tranche (#47).

PR #43 is the first direct Phil-wide design consequence of Steve Generalization 2. The recognized-record ABI distinguishes runtime primitive/signature identity, physical program-site identity, and exact assurance claim identity. PR #44 demonstrates that separation in implementation. PR #47 then proves the current **singleton-site** form in `PHIL-LLVM-RUNTIME-SYM-001`: linker identity depends on physical primitive/signature rather than revision/evidence/use identity, and one source physical site remains one LLVM call for the current host target. Crucially, #47 explicitly leaves arbitrary multi-claim claim-set preservation to the generalized physical-site model, so Steve Generalization 2 remains the next generic extension rather than being accidentally claimed complete.

PR #46 exercises the other side of that host target boundary with an actual C runtime fixture. It verifies fail-closed recognized-record status handling and full-width `Begin.length` dataflow through `receive_exact_u64`, and it adds an independent LLVM-signature conformance check before composition. The adversarial `ptr -> i32` accessor is important precedent: successful `llvm-link` is not itself evidence of exact ABI type equality. Target-realization validation must therefore check the semantic/ABI relation it relies on rather than treating successful composition as a conformance oracle.

ADR-012 sharpens how Steve should consume these precedents. The one-site/one-LLVM-call result is a host/LLVM specialization; the generic Systems rule is one exact assurance/cost-bearing site with an explicit selected-target realization relation. Stable assurance-subject identity likewise must not collapse to machine address, placement, storage class, or one runtime representation.

Steve rejected fixture 02 is promoted from parser-only status to a branch-local semantic test suite. `test/SteveSurfaceSemanticMain.hs` declares generic opaque `DigestMatches` and supplies the untyped `object` parameter as a generic stable `OwnedBytes` identity through the architecture environment; the existing checker must then reject generic `prove` with exactly `OpaqueProof`. This gives Steve its first checker-level semantic pressure test without adding Steve-specific Core logic. The stable identity is supplied explicitly because `OwnedBytes` does not currently expose a generic `.id` refinement projection.

Once the four Systems generalizations in `generalization-handoff.md` are available, the promotion target here is an honest executable Steve Systems artifact plus the adversarial mutations listed in the handoff and `lowering-contract.md`.
