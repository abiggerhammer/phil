# Steve systems-pressure-test material

`lowering-contract.md` is the current Steve 0 mapping from the semantic/assurance witness into Phil's ADR-007/010/011 Systems IR. It remains the design-level description of the intended `StevePut`/`SteveGet` control flow, ownership, runtime checks, cost model, and eventual executable-promotion criteria.

`generalization-handoff.md` is the implementation/proof handoff extracted from that pressure test. It turns the four representation gaps into concrete generic Haskell and Rocq targets:

- first-class assumption authority on stage facts, including mixed transferred-plus-assumption facts;
- multiple exact assurance claims on one physical runtime site without duplicating the physical cost, while keeping runtime primitive/signature identity, physical site identity, and assurance claim identity distinct;
- checked provider-capability possession and call authority, so absence of replace/delete authority is structural rather than inferred from unused calls;
- binding persistent assurance subjects to stable owner/storage identity while borrowed views remain observation mechanisms.

The material here is intentionally design-first rather than an executable `SystemsArtifact`. The current upload-derived Systems implementation and proof corpus should be generalized, not copied around with Steve-specific exceptions.

The branch is synchronized through main PR #43. That includes the Systems ownership/runtime proofs (#31), LLVM translation-validation proofs (#33), runnable compiler and typed scalar path (#32/#34), concrete Phase 0 LLVM translation certification (#35), the first real checked Surface -> Systems scalar SSA/dataflow lowering (#36), the Core/Systems/LLVM scalar proof tranche (#37), semantic field projection with shared scalar dominance/dataflow (#38), mechanized Surface -> Systems scalar projection plus SSA/dataflow integrity (#39), the first Phil-native Rocq proof-certificate path (#40), recognized-record ABI v1 (#41), certified field-projection proofs (#42), and the runtime-symbol identity amendment prompted by Steve Generalization 2 (#43).

PR #36 satisfied the implementation side of the first sequencing item in `generalization-handoff.md`: establish a generic checked Surface -> Systems lowering path before attempting Steve-specific resource/provider lowering. PR #39 supplies the matching proof side for that scalar slice. PR #38 adds a useful neighboring precedent: a semantic field is materialized only after its recognition gate, with an explicit witness, lowering decision, and shared scalar dominance check, while the concrete record ABI remains deliberately undecided. PR #40 establishes the certificate pattern we will want once Steve's own obligations become mechanically discharged: exact proof source/object bytes become a content-addressed `ProofAssistantTheorem` certificate selected by the assurance manifest, with residual trust boundaries left explicit rather than being silently promoted to `KernelChecked`. PR #42 confirms that this certificate path generalizes to later Systems/LLVM proof obligations rather than remaining a scalar-only specimen.

PR #43 is the first direct Phil-wide design consequence of Steve Generalization 2. The recognized-record ABI now distinguishes three identities that the handoff must keep separate: runtime primitive/signature identity, physical program-site identity, and exact assurance claim identity. Multiple physical sites may invoke one primitive; one physical site may justify multiple claims; changing the claim set must not by itself rename the linker-visible primitive or duplicate execution/cost. This prevents the old one-evidence-per-site representation from leaking into the runtime ABI before an implementation artifact freezes it.

Steve rejected fixture 02 is also promoted from parser-only status to a branch-local semantic test suite. `test/SteveSurfaceSemanticMain.hs` declares generic opaque `DigestMatches` and supplies the untyped `object` parameter as a generic stable `OwnedBytes` identity through the architecture environment; the existing checker must then reject generic `prove` with exactly `OpaqueProof`. This gives Steve its first checker-level semantic pressure test without adding Steve-specific Core logic. The stable identity is supplied explicitly because `OwnedBytes` does not currently expose a generic `.id` refinement projection.

Once the four Systems generalizations in `generalization-handoff.md` are available, the promotion target here is an honest executable Steve Systems artifact plus the adversarial mutations listed in the handoff and `lowering-contract.md`.
