## The scope boundary of commutation

The earlier [disjoint-Ping-pair slice](formal-semantics-source-ping-disjoint-pairs-fsem02-v1.md) established two-pair commutation only with four distinct participant process keys. This slice intentionally overlaps: two joint Send/Receive requests share the **same** Client process and exact source-derived linear predecessor, but address separate active Server processes. Their schedules need not commute.
