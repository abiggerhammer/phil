# FSEM-02: exact restricted rendezvous predecessor replay (non-normative)

Tracking [issue #1613](https://github.com/abiggerhammer/phil/issues/1613). This bounded source-to-Core correspondence hardening follows [#1699's close replay](formal-semantics-terminal-close-replay-fsem02-v1.md) and [#1704's source carrier checks](formal-semantics-source-close-carrier-fsem02-v1.md) without changing normative syntax, semantic contracts, architecture admission or the trusted computing base.

**Operational premise:** `(instance, network, predecessor, checked-source-send/receive, cachedRendezvous, cachedCloses, disposals, obligations, rootResidues)` is supplied to `grammarV1CheckRestrictedSourceTerminal`. The original activation-derived `predecessor` includes all Core per-process protocol/resource contexts and its exact owner-occurrence index. Nominal roles, message boundary authorization, activation occurrence identity, and process network admission are independently supplied; neither code nor proof derives them from source names. Source send/receive/close binder identities have already been checked by the existing production Grammar-v1 adapters.

**Rule:** the existing checker independently replays both native Core End closures from the cached post-rendezvous state and compares the entire post-close Core state. It **also** invokes `checkRestrictedProcessRendezvous instance network predecessor (restrictedSourceRequest cachedRendezvous) (restrictedSourceTransfer cachedRendezvous)`. A Core predecessor rejection returns `RestrictedSourceTerminalRendezvousReplayError` retaining the original exact `ProcessRendezvousError`; an unequal successor returns `RestrictedSourceTerminalRendezvousStateMismatch`. Both reject without a successor. Equality includes the complete Haskell protocol/resource contexts and activation-owned occurrence map, not just two endpoint names or the payload owner. Only after both exact replays can existing production process/root terminal checks run.

**Executable witnesses:** the real parsed `test/fixtures/fsem02-restricted-source-transfer-v1/accepted.phil` is replayed deterministically; the one-token-change `rejected-stale-close.phil` still rejects as `GrammarV1ComponentSendCloseCloseMismatch`. `test/Phase1FSEM02RestrictedSourceTransferMain.hs` also rejects a forged cached affine resource that itself permits valid Core close transitions, a missing original payload occurrence (exact `RestrictedMessageOwnerUnknown`), and an incorrect original session head (exact `RendezvousProtocolError` and process identity). All earlier stale, role, session, ownership, close and terminal-obligation negatives remain active.

**Rocq:** `proof/Phil/Core/FSEM02PredecessorReplay.v` proves conditional exact owner equality at observed keys, two-key composition, and rejection for failed replay, invented or altered owner entries. The proof models only a finite observation projection of an abstract owner function. Actual Haskell full-state equality, exact source parser and typed carrier correctness, network/role authority, source-authorized disposal, universal Haskell-to-Rocq refinement and full source operational semantics are **not proved**. FSEM-02 and subsequent families remain open; no normative, fairness, progress, termination or deadlock-freedom claim is made.

**Pre-PR verification:** `.github/workflows/fsem02-restricted-predecessor-preflight.yml` runs warning-free production Haskell/parsed-source replay and Rocq 9.2 with an admission scan.
