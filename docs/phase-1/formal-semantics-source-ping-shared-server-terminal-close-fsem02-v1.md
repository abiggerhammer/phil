## New boundary beyond shared-Server first-step contention

The [shared-Server one-use slice](formal-semantics-source-ping-shared-server-contention-fsem02-v1.md) shows that either independently activated Client may win the same Server Receive predecessor, and the loser cannot consume it again. The present test **continues the winning Send/Receive to both exact typed terminal End closures**. The independently checked [accepted Ping source](../../test/fixtures/fsem02-protocol-progression-v1/accepted.phil) supplies the actual Client and Server endpoint binders, successor identities and projected dual heads; the [minimally rejected stale-close source](../../test/fixtures/fsem02-protocol-progression-v1/stale-close.phil) is separately checked for its exact binder-mismatch rejection class.

For either choice of first sender, the real production `checkProcessCommunication` transition installs the winning Client's and shared Server's exact End successor endpoints and linear owners. Actual `checkProtocolAction (ProtocolCloseRequest ... Done)` calls then consume each End successor without replacement. Closing the winning Client before the shared Server or vice versa yields identical full finite process maps. Both terminal endpoint metadata and both linear owners are absent, while the **unselected Client retains its original Send head** and an independently activated affine spectator retains its complete active loan. The process-key population stays fixed.

A losing attempt after both Closes must still reject `RendezvousEndpointNotOwnedByProcess` for the consumed Server Receive predecessor; replaying the winner instead rejects its own consumed Client Send predecessor first. Repeating either Close must reject with exact `ProtocolEndpointUnknown` for that End successor. These are negative outcomes with no new successor, not source-authorized reactivation. Both alternate initial winners can be replayed deterministically from the same immutable prestate.

## Conditional proof and exact trust boundary

[Six Rocq 9.2 lemmas](../../proof/Phil/Core/FSEM02PingSharedServerTerminalCloseFrame.v) model local terminal disposal as explicit finite-map resource-context replacement after a successful shared-Server one-use step. They prove pointwise commutation of two distinct process replacements, exact final Client and Server slots, framing of any third process, refusal of missing first-step evidence, and non-rearming when the externally supplied availability flag is false. **These lemmas do not prove that an arbitrary native `ProtocolCloseRequest` implements the replacement model.**

The `nat` process-key representation, finite-map fidelity, source-to-native request construction, nominal binary protocol instance and roles, extra activated Client and spectator, terminal disposal permissions, selected root, assurance and external scheduler choices remain **premises**. Neither the source syntax nor a successful test manufactures authority. No global Haskell-to-Rocq simulation, FSEM-05 extracted interpreter, FSEM-06 differential refinement, fairness, or FSEM-07 normative graduation is claimed.
