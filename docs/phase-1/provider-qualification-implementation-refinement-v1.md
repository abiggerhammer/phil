# PROV-001–005 implementation refinement v1

`PHIL-PROV-QUAL-IMPL-001` mechanically links the stateless provider qualification production checker to its certified Rocq semantics.

Provider qualification is the first migration with nested finite maps: public operations, explicit operation correspondences, implementation entries, implementation outcomes, and mapped public outcomes. The migration factors a reusable finite-association support kernel and builds the actual provider traversal on top of it rather than trusting a second handwritten semantic walk.

The checked-in support kernel provides exact pairwise key-domain comparison for canonical association lists, exact association-list lookup, and universal finite Boolean traversal. Rocq proves key-domain comparison equivalent to equality of finite key projections when concrete key equality is exact, proves lookup soundness and unique-key completeness, and proves finite Boolean traversal equivalent to `Forall`.

The extracted `ProviderQualificationKernel` owns the nested production decision. `decideProviderQualification` checks exact contract and implementation revisions, exact public-operation/correspondence key domains, explicit correspondence lookup for every public operation, exact implementation-entry lookup, a supplied per-operation semantic acceptance predicate, exact implementation-outcome/mapping key domains, mapped public-outcome lookup, and exact resource-residue equality.

The per-operation predicate is the bounded composition point for the already `Implementation Refined` CALL-012 production checker plus the no-stronger-preconditions condition. A callable refinement rejection therefore cannot be repaired by provider-level correspondence, and provider-level acceptance cannot bypass CALL-012.

Production `checkProviderSemanticQualification` now constructs canonical ascending association-list projections and delegates the acceptance decision to the extracted provider kernel. Before delegation, every concrete provider `Map` and provider-owned `Set` used by the projection is round-tripped through its canonical ascending representation; any inconsistency fails closed. The previous handwritten traversal remains only for detailed diagnostic/result reconstruction. It cannot turn an extracted rejection into success, and any disagreement between the extracted decision and diagnostic reconstruction fails closed as `ProviderQualificationRepresentationMismatch`.

The checked-in `src/ProviderQualificationKernel.hs` is the exact artifact generated by the green #233 extraction run, SHA-256 `100b79e2a65c6c5dcdd433dde3a8b67b86de04018f18c8f9eb2fc43f4ba33344`. CI recompiles the bridge and nested traversal, regenerates both provider kernels, requires byte-identical equality with the checked-in modules, typechecks the production provider path inside Cabal's dependency environment, and runs both the CALL-012 and PROV-001–005 behavior corpora through the bound path.

Rocq extraction/toolchain correctness, GHC/Haskell runtime behavior, concrete equality and `containers` canonical Map/Set semantics, production construction of provider contracts/claims, and the semantic truth of provider inputs remain named TCB components. Provider-wide PROV-006+ state, law, lifecycle, authority, and evidence layers remain outside this bounded stateless slice.

An exact-head green closeout of this production-bound tranche is the remaining condition for `PHIL-PROV-QUAL-IMPL-001` to become `Implementation Refined`.
