# Phase 1 IO FileSystem proof boundary v1

`PHIL-P1-IO-FS-001` certifies the semantic state relation for bounded binary reads and process-observable replacement.

## Owned semantic facts

The Rocq proof owns these facts over already-semantic Path and runtime Bytes values:

- every accepted read uses a Path whose exact FileSystem occurrence matches the selected occurrence;
- an accepted successful read is the exact semantic binding and is within the caller limit;
- accepted `TooLarge` requires an existing binding whose runtime length exceeds the limit;
- accepted `NotFound` requires no binding;
- portable negative reads do not mutate semantic filesystem state;
- every read leaves semantic filesystem state unchanged;
- successful replace installs the supplied runtime Bytes at the selected Path and is observable by a subsequent semantic lookup;
- failed replace preserves the prior semantic state exactly; and
- read and replace are distinct filesystem operations.

The executable implementation model also mirrors the Haskell checker order:

1. exact Path/FileSystem occurrence match;
2. nonnegative Haskell read limit;
3. already-certified authority admission;
4. outcome validation.

For successful reads, binding presence is checked before exact content and exact content before the bound. `TooLarge` is accepted only for an existing oversized binding. `NotFound` is accepted only for an absent binding. Other typed portable negatives are accepted after the common preconditions.

## Imported predecessor boundaries

This proof does **not** re-prove:

- canonical provider-relative Path identity (`PHIL-P1-IO-PATH-001`);
- runtime-sized Bytes semantics (`PHIL-P1-IO-BYTES-001`);
- authority possession/competence;
- occurrence-indexed effect identity; or
- provider realization qualification.

Those are predecessor obligations. `FileSystemAuthorityAccepted` is therefore an imported semantic fact rather than a new authority checker.

## Native / realization boundary

The following remain native implementation or realization facts:

- `Data.Map.Strict` representation and lookup/insert implementation;
- Haskell `Int` representation and the concrete negative-limit test;
- concrete `RuntimeBytes` carrier representation;
- conversion of authority checker results into the imported acceptance fact;
- host filesystem calls, host paths, errno/platform error translation, durability, crash consistency and atomic replacement mechanisms.

The semantic state is a conformance oracle, not a claim that production must use an in-memory map.

## Implementation refinement

This certification slice does not yet production-bind an extracted IO-FS kernel. After it lands, a successor may extract only the ordered read/replace admission decision surface and bind `Phil.IO.FileSystem` to those exact generated bytes, while leaving Map/Int/Bytes fact extraction and authority checking at their existing boundaries.
