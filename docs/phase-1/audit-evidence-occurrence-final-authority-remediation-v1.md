# Phase 1 audit remediation: accepting-operation reflection

This implementation-side remediation closes the remaining native correspondence edge after exact same-event subject endpoint preservation.

## Supported final-closure witness

The supported original-event final-closure route now has an authoritative successful-return value. It is constructed only after all of these steps succeed in one call:

1. derive the complete ordered evidence-use inventory from the authentic returned `ValueResult`;
2. derive the exact event-qualified subject endpoints from the same result and `ResidualSpec`;
3. derive the assurance handoff from that same original event;
4. submit that handoff, the caller's exact `ManifestClosureSelection`, and the supplied immutable evidence bindings to `closeVerificationBundleWithHandoff`; and
5. retain the resulting manifest together with the exact inputs above.

The compatibility API that returns only `AssuranceManifest` delegates to this authoritative route and projects the manifest. Choosing the older return type therefore cannot skip accepting-operation reflection.

## Correspondence boundary

This is a scoped Phase 1 witness for the actual successful accepting operation. The checker-derived occurrence domain is not reconstructed by the caller, and endpoint metadata is not an optional report. Repeated subject positions remain distinct occurrences even when they legitimately share one event-local subject identity.

The final assurance-use selection remains a caller-supplied premise. The witness records the exact selection that the immutable closure accepted; it does not claim to derive architecture packaging, evidence selection, exports, assumptions, or assurance-use policy from the checker result.

## Non-claims

This repair does not introduce global subject identities, infer cross-event equality, manufacture a checked rebase from spelling/type/index equality, interpret missing endpoint metadata as closedness, or restore consumed Affine/Linear ownership. Residual-free final entry remains restricted by the existing producer-association boundary. LLVM remains inside the Phase 1 trusted computing base.

## Permanent control

The original-event final-closure regression now checks that a successful authoritative closure returns:

- the exact `ResidualSpec`;
- the exact `actualEvidenceUseInventory result`;
- the exact `actualEvidenceSubjectEndpoints spec result`;
- the exact event-derived handoff entries;
- the exact `ManifestClosureSelection`; and
- the same manifest returned by the legacy projection, including the accepted assurance-use set.
