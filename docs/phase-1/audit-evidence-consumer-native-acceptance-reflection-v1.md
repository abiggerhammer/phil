# Phase 1 audit: native accepting-return reflection for evidence occurrences

This defensive proof-correspondence slice continues D-RES-SUPPORT-01 / D-RES-TREE-01 after occurrence-level final authority.

The previous proof establishes the required event/consumer/occurrence/source/target predicate once the relevant domain and final accepting operation have already been reflected into the proof model. The native implementation now has a mandatory authentic returned-use/occurrence inventory and endpoint check before immutable closure. The remaining boundary is therefore the reflection of a **successful native wrapper return** into the exact proof-side domain and tuple data.

The new proof makes four requirements explicit:

- the native returned evidence-use domain is exactly the proof model's actual-use domain;
- the native subject-occurrence domain is exactly the proof model's actual-occurrence domain for each returned use;
- the native event and source/target endpoint tuples are the same tuples used by original/final-use and occurrence authority; and
- successful acceptance retains final-assurance use selection and fixture-owned architecture/evidence packaging as visible premises.

The negative controls show that a complete proof over a smaller supplied domain does not certify an extra native use, mismatched event metadata does not qualify the tuple, and neither final-assurance selection nor architecture/evidence packaging may be silently omitted.

The positive multi-subject control preserves repeated positions without inventing distinct semantic identities. The checked-closed control has no subject occurrence or endpoint, but it still carries exact event, selection, and packaging premises.

## Native correspondence boundary

This proof does not manufacture the native relations. Production Haskell remains responsible for deriving the domain from the authentic returned result, deriving competent endpoints from validated durable support, carrying the same event into the handoff/bundle and selected-evidence checks, and identifying the actual accepting operation.

Local indices are result-local coordinates, not global subject or event identities. Name/type/index equality does not create a rebase or cross-event identity. Missing endpoint metadata is not a closed-use classification, and structural closedness is not discharge.

This slice changes only a Rocq module, this note, and an isolated proof workflow. It does not modify production Haskell, source admission, ownership, native lowering, packaging, or any Phase 1 trusted-computing-base boundary. LLVM remains trusted in Phase 1.
