# Provider lineage core implementation refinement v1

This staging slice mechanically connects the already-Certified `PHIL-PROV-LINEAGE-CORE-001` semantics to an executable Rocq-extracted decision surface without changing production behavior.

## Certified surface

`proof/Phil/Core/ProviderQualificationLineageCore.v` separates provider qualification claim, evidence, and contextual admission identity and defines dependency grounding as the least relation generated by independent accepted grounds and dependency inheritance.

## Extracted staging decisions

`proof/Phil/Core/ProviderQualificationLineageCoreImplementation.v` extracts:

- exact claim/evidence/admission identity classification;
- exact dependency registry-key classification;
- known-root classification;
- ordered reachable-node validation for admission acceptance, admission dependencies, ground references, and ground acceptance;
- per-ground monotone propagation through dependency edges;
- final reachable-grounding admission.

The identity decision is proved exactly equivalent to the Certified `AdmissionBindsClaimAndEvidence` predicate after reflecting exact revision/interface equality with `Nat.eqb`.

For PROV-012, the extracted kernel deliberately owns the semantic propagation step rather than accepting one opaque native `grounded` fact. `propagateGroundPresence own dependencies` is proved true exactly when the admission already has that ground or at least one dependency has it. Separate theorems prove direct-ground preservation, inherited-ground propagation, and rejection of self-endorsement when neither direct nor dependency ground is present.

## Native staging boundaries

Production remains unchanged in staging. Concrete `Text` identity, `Map`/`Set` construction and ordered traversal, registry lookup, reachable-node enumeration, finite fixed-point scheduling/stability equality, diagnostic payload reconstruction, canonical serialization/revision construction, and truth/validity scope of independent grounds remain explicit native or evidence boundaries.

A production-binding closeout may keep those representation operations native, but must route the semantic identity/validation classifications and each concrete per-ground fixed-point propagation membership through the exact checked-in extracted kernel. Any concrete/kernel shape disagreement must fail closed.

## Staging gates

The dedicated lineage-core workflow:

1. compiles the Certified proof and implementation correspondence with Rocq 9.2.0;
2. fresh-extracts `ProviderQualificationLineageCoreKernel.hs`;
3. strict-typechecks and executes direct controls against the fresh kernel;
4. strict-typechecks unchanged `ProviderQualificationIdentity.hs` and `ProviderQualificationDependency.hs`;
5. reruns the unchanged PROV-011/012 correspondence corpus;
6. records proof, kernel, production, test, harness, and document identities.

A green staging run leaves `PHIL-PROV-LINEAGE-CORE-001` at `Discharged / Certified`. `Implementation Refined` requires a separate production-binding closeout.
