For each of the three modes, the expected precedence and repair sequence is: (1) exact RestrictedMessageSenderResourceError sender (UnknownBinding ownerName), with or without occupied receiver; (2) repairing *only receiver* retains that same absence error; (3) repairing *only sender* exposes exact RestrictedMessageReceiverResourceError receiver (DuplicateBinding destination); (4) repairing both reconstructs the original state and permits source-accepted endpoint/payload owner transition and spectator preservation; (5) the one-operand wrong Close is still rejected exactly as GrammarV1ComponentSendCloseCloseMismatch before either Core fault. Every failure is a pure Left and yields no transition successor.

The deliberately missing native entry is a **corrupt post-activation test state**, not a newly authorized activation or valid source-side resource. The independent owner occurrence is a premise, never inferred from payload spelling. The regression reuses original checked protocol instance, roles, dual heads, sender/receiver identity, process network and terminal outcome contracts; selected-root, disposal and assurance authority remain external.
