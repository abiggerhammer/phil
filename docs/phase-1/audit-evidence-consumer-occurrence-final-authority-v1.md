# Phase 1 audit: same accepting operation for evidence occurrence authority

This defensive proof-correspondence slice continues D-RES-SUPPORT-01 / D-RES-TREE-01 after competent semantic endpoint authority.

The existing chain now establishes exact actual-use and subject-occurrence coverage, same-event final-use correspondence, approved original-event origin, and competent semantic source/target endpoint authority for every actual subject-bearing occurrence. The live independent handoff keeps one further boundary explicit: an endpoint map or separately reconstructed support graph is not final-consumer correspondence. The exact occurrence tuple must be the one credited by the actual accepting operation.

`EvidenceConsumerOccurrenceFinalAuthority.v` therefore adds one bounded composition boundary:

- every actual subject-bearing occurrence keeps the exact event, use, occurrence, source endpoint, and target endpoint already established by the prior chain;
- that same exact tuple must be credited by the final accepting operation;
- complete semantic endpoint authority without final occurrence credit is insufficient;
- the positive multi-subject witness preserves both occurrences and their exact endpoint tuples through the accepting consumer; and
- genuinely checked closed uses still require no fabricated subject occurrence or endpoint authority.

## Native correspondence boundary

The proof intentionally does not manufacture the final relation. Production remains responsible for reflecting the authentic returned `ValueResult.valueResultEvidence` use/occurrence domain, competent declaration/binding/checked-rebase endpoint authority, approved original-result/event association, and the real final accepting operation into this predicate.

Local use/occurrence indices remain coordinates inside one authentic result, not global semantic identities. Source spelling, matching types, index equality, a caller-supplied event label, or an optional endpoint map cannot establish final-consumer authority. Logical subject survival remains separate from one-use resource permission, and consumed Affine/Linear ownership is not restored.

This proof also does not require a generalized Phase 2 subject registry. A scoped Phase 1 implementation may enforce only the explicitly supported final-closure boundary.

## Acceptance cases

1. Complete competent semantic endpoint authority with no final occurrence credit is insufficient.
2. A complete two-subject use succeeds when both exact occurrence endpoint tuples are credited by the same accepting operation.
3. A checked closed use succeeds without invented occurrence endpoints because it has no actual subject occurrence.

This slice changes only a Rocq proof module, this note, and an isolated proof workflow. It does not modify production Haskell, source admission, ownership/loan semantics, native lowering, packaging, or any Phase 1 trusted-computing-base boundary. LLVM remains trusted in Phase 1.
