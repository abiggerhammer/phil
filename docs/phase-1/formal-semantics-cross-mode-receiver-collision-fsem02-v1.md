# FSEM-02: cross-mode receiver name exclusivity in restricted transfer

**Non-normative bounded Haskell source/native test plus separate conditional Rocq 9.2 model.** Tracks [#1613](https://github.com/abiggerhammer/phil/issues/1613) and extends the typed-sender-before-linear-receiver-collision slice in #1895.

## Explicit premises, transition and exact diagnostics

The checked complete Grammar-v1 restricted `Bytes[8]` Send/Receive fixture is parsed by the production source adapter. The actual `ResourceContext` has unrestricted, affine, and linear maps; its production `insertBinding` refuses a new binding when the **same resolved name** is already present in *any* structural mode. The sender payload is still a restricted linear resource, and the requested receiver binding is linear. Protocol instance, selected roles, message boundary certificate, activation/owner index, predecessor heads, message binder and authorization remain independently supplied premises; none can be inferred from source spelling.

For **each** hostile receiver state, one with an affine `TyBool` resource and one with an unrestricted `TyBool` resource at the exact intended receiver name, the receiving **linear** map remains vacant. Production replay with a valid sender must return exact `RestrictedMessageReceiverResourceError process (DuplicateBinding name)`; neither state can be treated as an alternate legal insertion mode. Simultaneously forging the sender's actual linear payload to `U8`, while external message authority still requires `Bytes[8]`, must return `RestrictedMessageTransferTypeMismatch` **first**. Repairing only the receiving collision leaves the sender type refusal; repairing only the sender exposes the receiver duplicate refusal. Repeating a hostile replay cannot acquire a partial successor.

The accepted, independently activated source fixture retains exact predecessor consumption, endpoint successors, payload ownership transfer, and the separate affine spectator. A **minimally rejected complete source** changes only sender `close done;` to `close endpoint;`; production source validation must return `GrammarV1ComponentSendCloseCloseMismatch` before either externally corrupted resource state is checked. Deliberately forged maps are *not* valid activations.

The [production executable regression](../../test/Phase1FSEM02RestrictedSourceTransferMain.hs) checks both occupied non-linear modes and error provenance; [eight Rocq lemmas](../../proof/Phil/Core/FSEM02CrossModeReceiverCollision.v) independently prove conditional finite gate ordering, mode-occupancy refusal with no successor, and modeled exact transfer/spectator framing after repairing all premises. They **do not** prove native Haskell `Map`/type/structural mode fidelity, total source-to-Core refinement or cross-language equivalence.
