# MHB lint rule registry

This document seeds a Clippy-like lint layer for the Mecha Hamster Ball shell.

The goal is not to duplicate semantic review. MHB lint reports mechanically
checkable violations of lane authority, revision identity, evidence census,
mutation scope, and related shell invariants using stable diagnostic IDs.

## Diagnostic shape

A diagnostic should have:

- stable rule ID,
- severity,
- short machine-readable name,
- human-readable explanation,
- relevant subject identifiers (lane, PR, revision, path, check, evidence),
- enough observed/expected data to reproduce the failure,
- no mutation side effects.

Initial output should be deterministic for the same repository/GitHub state.
The eventual serialized form should be suitable for both human display and
substrate-independent hamster consumption.

## Initial rules

### MHB001 — unsupported-lane

**Severity:** error

The requested or inferred lane is not one of the shell's supported lanes.

Current bridge coverage:
- `hamster-auto-pr.yml`
- `hamster-merge-intent.yml`
- `hamster-generated-refresh-intent.yml`

### MHB002 — lane-label-mismatch

**Severity:** error

The PR's native `lane: <lane>` label is absent or disagrees with the
authorized lane.

This prevents body text or branch prose from silently defining authority.

### MHB003 — lane-head-ownership-mismatch

**Severity:** error

The PR head branch is not owned by the authorized lane, e.g. it does not match
`hamster/<lane>/...`.

The lane label and branch ownership must agree independently.

### MHB004 — stale-exact-head

**Severity:** error

The live PR head is not the exact revision named by the authorization or
evidence request.

A later green revision does not satisfy evidence or authorization for an older
revision, and an older green revision does not authorize mutation of a newer
head.

### MHB005 — incomplete-check-census

**Severity:** error

The exact-head check-run census is empty or incomplete.

"All returned checks are green" is insufficient if the returned set is not the
complete set reported for that revision.

### MHB006 — unsuccessful-exact-head-check

**Severity:** error

At least one exact-head check is not completed successfully.

The diagnostic should name every non-successful check and report its status and
conclusion.

### MHB007 — intervening-main-overlap

**Severity:** error

The PR was based on an older main revision and files changed on main since that
base overlap files changed by the PR.

The shell must refuse to infer merge safety from green checks run against a
non-current base when intervening work touches the same files.

### MHB008 — unauthorized-generated-path

**Severity:** error

A repository-side generated-refresh operation attempts to modify a path outside
the whitelist for its authorized generator family.

The model supplies an intent tuple, never generated bytes or a free-form path
set.

## Next rule families

These should follow once their evidence schemas are stable enough to make the
checks deterministic.

### Authority and provenance

- proposal promoted to obligation without a recorded decision edge,
- obligation or acceptance criterion lacks source authority,
- evidence refers to a different lane, subject, or revision,
- generated evidence lacks generator/version provenance.

### Verification closure

- required checker/evidence inventory is incomplete,
- a required proof/module/artifact is absent from the authoritative census even
  though all enumerated checks are green,
- closure is inferred from missing mappings,
- returned manifest does not bind the exact checker-derived inventory and
  selected evidence.

### Mutation admissibility

- lane attempts a path or mutation class outside its authority,
- contract/obligation change is presented as an implementation repair,
- consumed ownership is reconstructed rather than rejected,
- generated refresh changes non-generated material.

### Completion discipline

- lane declares `Done` without satisfying its finite completion predicate,
- lane invents successor work after completion,
- `Blocked` lacks a concrete blocking observation,
- retry behavior changes the requested semantic slice.

## Implementation direction

Start with a repository-side command whose pure core consumes a snapshot and
returns diagnostics. GitHub/API collection should be a thin adapter.

That separation is intentional:

1. snapshots can be replayed in tests,
2. independent implementations can consume the same snapshot format,
3. model substrates do not become part of the checker,
4. diagnostics can later be cross-checked by a second implementation.

The first implementation should cover MHB001–MHB008 before expanding into
semantic/provenance rules.

## Non-goals for the first slice

- proving Phil semantics,
- deciding whether a theorem is the intended theorem,
- interpreting free-form hamster reasoning,
- silently repairing violations,
- weakening obligations to make a candidate pass.

MHB lint reports shell-policy violations; it does not redefine success.
